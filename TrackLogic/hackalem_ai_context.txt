HACKALEM AI 2026 - КОНТЕКСТ ПРОЕКТА

ЦЕЛЬ
Готовим HackAlem AI 2026. Цель - за 5 часов вайбкодингом через Codex собрать сильный AI-agent для строительной отрасли.

КЛЮЧЕВАЯ КОНЦЕПЦИЯ
Не делаем один узкий AI-сервис и не делаем обычный чат-бот.
Делаем единую AI-платформу для стройки - AI Construction OS.

Один AI-агент получает задачу и может работать со всей цепочкой:
Продажи -> Смета -> Закупки -> Склад -> Производство -> Проект -> Контроль -> Финансы.

АГЕНТ
GPT используется через OpenAI API. LLM находится на стороне OpenAI.

Схема:
Пользователь
-> OpenAI/GPT
-> GPT выбирает tool
-> наш backend выполняет tool
-> результат возвращается GPT
-> GPT анализирует
-> выбирает следующий tool
-> ...
-> результат/действие.

LLM = мозг.
Backend = исполнитель.
Наши API = tools/руки агента.
БД/CRM/склад/финансы = данные.
Agent loop = последовательность действий.

Пример:
"Подготовь производство заказа №152 и закупи всё недостающее."
GPT вызывает getOrder()
-> getWarehouse()
-> находит дефицит
-> findSuppliers()
-> сравнивает цену/срок
-> createPurchaseDraft()
-> планирует производство
-> выдаёт результат.

ВАЖНО
LLM не должна делать то, что обычный backend делает лучше:
- математика;
- суммы;
- остатки;
- НДС;
- проверки лимитов;
- детерминированные расчёты.

GPT отвечает за:
- понимание запроса;
- планирование;
- выбор tools;
- интерпретацию результатов;
- выбор следующего действия;
- финальный ответ.

ОПАСНЫЕ ДЕЙСТВИЯ
Например реальную закупку лучше делать с подтверждением:
AI -> "Создать закупку на 380 000 ₸?"
Человек -> Да
-> createPurchase()

СТЕК
При 100% вайбкодинге и 5 часах разработки выбран Python:
- Python
- FastAPI
- OpenAI API
- PostgreSQL
- Redis при необходимости
- Docker

Без Kubernetes, микросервисов и лишней enterprise-архитектуры.

Почему Python:
- меньше boilerplate;
- проще FastAPI;
- удобный OpenAI API;
- проще tool calling;
- проще менять код через Codex;
- огромная AI/ML экосистема;
- если понадобится локальная модель/fine-tuning, Python удобнее.

Java хорош для enterprise, но для 5 часов и вайбкодинга будет больше boilerplate.
Go тоже хорош, особенно если GPT полностью внешний, но Python лучше для AI/ML и возможного fine-tuning.

ТОКЕНЫ
Расход зависит не от Python/Java/Go, а от:
- размера prompt;
- количества данных;
- количества agent steps;
- размера истории;
- размера tool responses.

Не передавать GPT всю БД.
Tools должны возвращать компактный JSON.
Расчёты делать backend-кодом.
Для простых действий не обязательно вызывать GPT.

AI CONSTRUCTION OS

1. AI SALES AGENT
Запрос:
"Клиент хочет навес 6x4, цвет графит, до 15 октября."
Агент:
- понимает запрос;
- задаёт недостающие вопросы;
- формирует заказ;
- считает предварительную стоимость.

2. AI ESTIMATOR
Из описания/чертежа:
- материалы;
- количество;
- работа;
- себестоимость;
- маржа;
- итоговая цена.

3. AI PROCUREMENT AGENT
Если материалов не хватает:
- ищет поставщиков;
- сравнивает цены;
- сравнивает сроки;
- учитывает историю поставок;
- предлагает оптимальный вариант.

4. AI WAREHOUSE AGENT
Проверяет:
"Хватит ли материалов для выполнения всех текущих заказов?"
Сам находит потенциальные дефициты до остановки производства.

5. AI PRODUCTION PLANNER
Получает:
"15 заказов, 3 бригады, 2 станка, 20 дней."
Строит оптимальный порядок производства.

6. AI CONSTRUCTION PM
Следит за проектом.
Если материал задерживается:
- понимает проблему;
- проверяет альтернативных поставщиков;
- пересчитывает сроки;
- перестраивает план.

7. AI RISK AGENT
Ищет:
- просрочки;
- перерасход;
- нехватку материалов;
- проблемы поставщиков;
- перегрузку бригад;
- падение маржи.
Не просто сообщает, а предлагает действие.

8. AI FINANCIAL AGENT
Запрос:
"Почему прибыль по проектам упала?"
Сам идёт:
финансы -> заказы -> материалы -> закупки -> зарплата -> маржа.
Выдаёт объяснение причины.

9. AI DOCUMENT AGENT
Загружаются:
- смета;
- КП;
- договор;
- счёт;
- накладная;
- чертёж.
AI превращает документы в структурированные данные системы.

САМАЯ СИЛЬНАЯ ФИШКА
Не отдельные 10 чатиков.
Все агенты/инструменты работают в одном workflow.

Пример killer demo:
"Возьми заказ клиента и организуй его производство."

Агент:
1. Анализирует запрос.
2. Формирует спецификацию.
3. Считает стоимость.
4. Проверяет склад.
5. Находит дефицит.
6. Сравнивает поставщиков.
7. Формирует закупку.
8. Планирует производство.
9. Проверяет сроки.
10. Создаёт проект.

На экране желательно показывать timeline:
Order received
-> Specification created
-> Warehouse checked
-> Shortage detected
-> Suppliers compared
-> Purchase draft created
-> Production scheduled
-> Project ready

Позиционирование:
"Мы не сделали ещё один чат с GPT. Мы дали строительной компании AI-оператора, который самостоятельно работает со всей цепочкой строительства."

ПРЕДВАРИТЕЛЬНЫЙ ВЫБОР
Мы определились: делаем именно строительную AI-платформу с большим количеством сценариев, а не выбираем одну отдельную сферу/фичу.

При этом на хакатоне не нужно полноценно реализовывать все функции.
За 5 часов лучше сделать 5-6 действительно работающих tools:
Order
-> Estimate
-> Warehouse
-> Suppliers
-> Procurement
-> Production

Остальные возможности показать как roadmap/расширение платформы.

- Можно ли заранее написать boilerplate.
- Можно ли использовать существующий собственный проект.
- Можно ли использовать готовые open-source модели.
- Можно ли использовать сторонние API.
- Можно ли использовать локальные модели.
- Можно ли делать fine-tuning.

- Время pitch/demo/Q&A.
- Ограничения на заранее подготовленные данные.
