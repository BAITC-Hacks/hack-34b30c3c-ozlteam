# Frontend backlog: закупки и пополнение

Общие приоритеты и границы — [PROJECT_DIRECTION.md](../PROJECT_DIRECTION.md), полный контекст — [CONTEXT.md](../CONTEXT.md). P0/P1 ниже — локальная последовательность интерфейсных работ, она не заменяет приёмку M1–M5 и согласование контрактов данных с командой.

Актуально на 23.09.2026. Основной пользователь — менеджер закупок
Электрокомплекта. Рабочий путь: применённые данные → сохранённый расчёт →
проверка рекомендации → черновик → ручная корректировка → утверждение →
CSV/XLSX. Страница `/recommendations/demo` — изолированная песочница алгоритма:
её локальное подтверждение и CSV никогда не заменяют серверный заказ.

## P0 — следующий инкремент

| Задача | Интерфейс и функция | Зависимость / критерий готовности |
| --- | --- | --- |
| Сделать основной путь очевидным | `/recommendations` начинается со сводки рисков и черновиков; «Демо» явно помечено песочницей. Не выводить пользователя в старый stateless-сценарий из рабочего пути. | Использовать `GET /api/v1/overview`; сводка относится к одному последнему успешному расчёту выбранного склада. Базовый блок уже добавлен, нужен UX-проход на данных seed. |
| Отбор и формирование черновиков | Добавить фильтр поставщика, выбор всей доступной группы и сумму количества по поставщику; сохранить явное превью последствий. | `GET /replenishment/runs/{id}/recommendations` уже принимает `supplier_id`. Не допускать `blocked`, нулевые и уже распределённые рекомендации; не терять idempotency key. |
| Полное обоснование рекомендации | В detail показать не только счётчики, но и историю/прогноз, исключённые продажи, поступления в пути, предупреждения и свежесть источников. | Использовать сохранённый `RecommendationDetailOut`; не пересчитывать цифры на клиенте и не показывать отсутствующие данные как факты. |
| Операционный заказ | В карточке заказа добавить комментарий, удаление строки с причиной, журнал действий, а для интеграционного оператора — состояние и пакет 1С. | Контракты уже есть: `PATCH /orders/{id}`, `DELETE .../lines/{line}`, `GET .../audit`, `GET .../1c`, `POST .../1c/ack`. Учитывать `expected_version`, 409 и неизменность approved-снимка. |

## P1 — после P0

| Задача | Интерфейс и функция | Зависимость / критерий готовности |
| --- | --- | --- |
| Готовность данных | Отдельный экран после импорта: сопоставлено / с ограничениями / требует разбора, актуальность остатков и покрытие истории. | Нужен серверный агрегат качества; не рисовать вымышленные проценты. Правила и пробелы описаны в `docs/replenishment-process.md`. |
| Адаптер выгрузок партнёра | Мастер сопоставления «код в источнике → stable external_id → UUIDv7», с разбором неоднозначностей, листом/строкой происхождения и безопасным повторным импортом. | Требуется согласование схемы с партнёром. Нельзя объединять по похожему названию, терять ведущие нули или считать папки IEK/Systeme разными базами без подтверждения. |
| Переходы между данными и решением | Из запасов открывать тот же товар/склад в расчёте; в рекомендации — источник, остаток и входящую поставку. | Сохранять query-параметры и возвращать в исходный список с фильтрами. |
| Работа со справочниками | `/data/catalogs` уже даёт просмотр, поиск, фильтры и карточки. Следующий шаг — редактирование поставщиков, сроков, MOQ/кратности, товаров и категорий с источником изменения. | Нужны правила валидации и записи через нормализованные API; MOQ и кратность не смешивать. |

## P2 — чистка и качество

- Скрыть из навигации и поиска исторические логистические экраны и placeholder-маршруты, не относящиеся к пополнению.
- Проверить desktop и mobile: initial skeleton для каждого ожидающего блока, pending только на действии, `prefers-reduced-motion`, клавиатурная навигация по таблицам.
- Добавить e2e-сценарий: import → calculate → detail → draft → quantity reason → approve → export, плюс 409-конфликт и отсутствие права.

## Не делать в UI без отдельного решения

- Не отправлять заказ поставщику автоматически.
- Не выдавать экспорт CSV/XLSX или локальное демо-подтверждение за создание документа в 1С.
- Не строить предположения о stockout, lead time, клиенте или единице измерения из неполной выгрузки.
