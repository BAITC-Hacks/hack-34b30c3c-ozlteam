# Передача проекта агенту для подготовки правил дизайна

Снимок состояния: 11 сентября 2026 года. Проект: `hackalem-ai-base`.
Локальный путь: `/Users/panda/projects/hackalem-ai-base`.
Документ самодостаточен: его можно целиком передать другому агенту без истории чата. Пути ниже указаны относительно корня проекта; для просмотра файлов агенту потребуется доступ к репозиторию.

## Задача следующего агента

Подготовить правила дизайна для команды и AI-агентов, которые будут развивать этот стартовый проект на хакатоне. Сейчас требуется сформулировать дизайн-систему и правила её применения. Конкретная предметная область продукта ещё не задана.

Текущий экран Notes — технический пример, созданный при подготовке инфраструктуры. Его цвета, название, типографика и композиция не являются утверждённым пользователем фирменным стилем. Не следует превращать их в обязательные требования без отдельного решения.

## Подтверждённые требования пользователя

- Команда готовит основу для участия в хакатоне по разработке.
- Python backend: FastAPI, Pydantic, SQLAlchemy 2, Alembic.
- PostgreSQL с расширением pgvector для возможного будущего RAG.
- React SPA, отдельный backend API, возможность PWA.
- Рядом находится заготовка Telegram-бота на aiogram 3.
- Всё запускается Docker Compose одной командой; изменения исходников видны без постоянной пересборки.
- Backend: модульная архитектура в `Domains`, тонкие контроллеры, бизнес-логика в сервисах, доступ к данным в репозиториях; папки `models`, `DTO`, `resources` внутри домена.
- Frontend: страницы и компоненты, используемые только модулем, находятся в этом модуле; общие переиспользуемые компоненты — в общих папках.
- Не создавать огромные компоненты и файлы, объединяющие экран, сетевые запросы и всю логику. Разделять по ответственности.
- Переиспользуемая возможность с собственной логикой, например поиск, должна оформляться как подключаемый модуль.
- Для local и production подготовлены отдельные env-файлы.

Пользователь пока не выбирал UI-библиотеку, шрифт, палитру, тёмную тему, фирменный стиль, набор иконок или конкретные дизайнерские референсы.

Сейчас не установлены Tailwind, shadcn/ui, Radix, MUI, Ant Design, библиотека иконок, React Router, библиотека форм, менеджер глобального состояния или Storybook. Не нужно исходить из того, что они уже есть. Выбор новой зависимости следует объяснять пользой для команды и согласованностью архитектуры.

Стили пока глобальные, включая селекторы `header`, `footer`, `input`, `h1`, `h2`. CSS variables/design tokens, изоляция стилей модулей и полноценная система вариантов компонентов ещё не внедрены. Для роста проекта это область работы над правилами дизайна.

## Текущий демонстрационный интерфейс

Одна страница на `/`, язык интерфейса русский:

1. Шапка с текстовым знаком `h↗ hackalem` и подписью `TEAM WORKSPACE`.
2. Вводный блок «Большие идеи. Первый шаг — здесь.».
3. Белая карточка «Заметки команды» со счётчиком.
4. Подписанное поле ввода и кнопка «Добавить».
5. Пустое состояние либо список заметок с датой и кнопкой удаления.
6. Состояние загрузки и ошибка с кнопкой повторной попытки.
7. Подвал и отдельное приглашение обновить PWA при появлении новой версии.

Текущие значения для ориентира, не утверждённые дизайн-токены:

| Параметр | Реализация |
| --- | --- |
| Фон страницы / основной текст | `#f5f4ef` / `#172c35` |
| Карточки | белые, тонкая рамка, radius 20px |
| Основная кнопка | `#243d37`, белый текст, radius 9px |
| Акценты | приглушённые оливковые и зелёные оттенки |
| Шрифты | `Inter, ui-sans-serif, system-ui, -apple-system, sans-serif` |
| Подключение Inter | отдельный font-файл или импорт отсутствует; используется доступный fallback |
| Контейнер страницы | максимум 1120px, боковые отступы 40px |
| Заголовок h1 | `clamp(36px, 5vw, 58px)` |
| Адаптивность | один media query до 600px, отступы 20px, форма располагается вертикально |
| Фокус | `:focus-visible`, outline 3px |

Нет утверждённой шкалы отступов, полной типографической шкалы, каталога компонентов, правил motion, dark mode или проверенного контраста всех состояний. Не представлять базовую адаптивную вёрстку как завершённую проверку доступности.

## Поведение, которое дизайн должен учитывать

- Notes: заголовок от 1 до 200 символов; пробелы по краям обрезаются; пустое значение недопустимо.
- UI выводит до 100 заметок. API поддерживает `limit`/`offset`, но пагинации интерфейса пока нет.
- Во время загрузки/сохранения соответствующие действия блокируются; есть empty/loading/error/pending состояния.
- API вызывается относительными URL `/api`; Vite проксирует запросы в backend.
- Нет пользовательской авторизации: заметки общие. Кабинеты, роли и приватные данные пока не спроектированы.
- PWA содержит manifest и PNG-иконки, а production build генерирует service worker.
- В development service worker отключён, чтобы не мешать горячей перезагрузке.
- PWA кеширует оболочку, не ответы API. Без сети загрузка и изменение заметок недоступны; очереди offline-записи нет.
- Обновление PWA предлагается пользователю кнопкой, а не навязывается во время ввода.
- Бот — обычный Telegram polling-бот, не Telegram Mini App. У него нет отдельного веб-интерфейса.
- RAG пока ограничен установленным расширением vector; чат, загрузка документов, retrieval UI и pipeline не реализованы.

## Запуск и окружения

```sh
make dev          # создать .env.local при отсутствии и поднять Docker в фоне
make dev-logs     # логи
make dev-ps       # состояние
make dev-down     # остановить, сохранить базу
make dev-bot      # запуск с ботом, требуется BOT_TOKEN в .env.local
```

Без Make: `./scripts/dev.sh up --build -d`.

- Интерфейс: http://127.0.0.1:5173
- Swagger: http://127.0.0.1:7575/docs
- Health: http://127.0.0.1:7575/api/health/ready

Используйте `127.0.0.1`: при предыдущей проверке `localhost:5173` в браузере попадал на другое локальное приложение.

`scripts/dev.sh` явно выбирает `.env.local`. Рабочие `.env.local` и `.env.production` исключены из Git, а `.env.local.example` и `.env.production.example` предназначены для передачи команде. Секреты в этот документ не включены.

`.env.production` подготовлен с пустыми секретами. Production Compose, сервер статических файлов и публичный HTTPS-деплой ещё не подготовлены. Текущий `compose.yaml` — только development.

В предыдущих шагах этой сессии успешно выполнены:

- Сборка и запуск development-контейнеров; API и база прошли healthcheck.
- 6 backend-тестов, включая реальную БД, rollback и оператор vector distance.
- `alembic check`: расхождений схемы и моделей не найдено.
- Backend lint/format, сборка и проверка импортов бота.
- TypeScript/Vite build, генерация manifest/service worker.
- Создание, сохранность после обновления страницы и удаление заметки через браузер.
- HMR фронтенда и reload API подтверждены логами при изменении исходников.
- `make dev`, автоматическое создание локального env, сохранение уже существующего env и правила исключения env из Git.

Полноценный аудит доступности, кроссбраузерная матрица, реальная установка PWA на устройства и работа Telegram с настоящим токеном не подтверждены. При подготовке этого экспорта исходники перечитаны; весь набор тестов повторно не запускался.

## Рекомендуемый результат работы над правилами

Это предлагаемый формат передачи результата, не уже утверждённые пользователем решения:

1. `docs/design-system.md`: единый источник правил — визуальные принципы, семантические токены, типографика, отступы, сетки, responsive, состояния, доступность, иконки и motion.
2. `.agents/skills/project-design/SKILL.md`: компактные инструкции для агента с отсылкой к документу; не дублировать целиком существующий frontend skill.
3. Ссылка на новый skill в `AGENTS.md`.
4. Разделение утверждённых требований пользователя и предлагаемых решений, особенно по UI-библиотеке, брендингу и dark mode.
5. Правила размещения общей UI-системы в `shared`, а предметных компонентов — в `modules`; ясный способ предотвращать глобальные CSS-конфликты.
6. Если нужна миграция текущего UI — отдельный короткий план. Не выдавать написанные правила за уже внедрённый редизайн.

Для значимых решений пока не хватает предметной области, целевой аудитории, ключевых сценариев и предпочтений по визуальному стилю. Сначала отделить универсальные правила реализации от этих открытых продуктовых решений.
