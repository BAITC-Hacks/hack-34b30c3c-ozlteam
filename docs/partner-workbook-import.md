# Выгрузки 1С: поставщики и товары

Книги из `TrackLogic/IEK` и `TrackLogic/Systeme electric` — тестовые данные
Электрокомплекта. IEK и Systeme Electric являются поставщиками одной компании,
а не двумя базами 1С. Синтетический seed остаётся отдельным источником.

## Сценарий пользователя

1. На `/data` выберите пакет исходных XLSX и загрузите книги вместе.
   Сервер сохранит оригиналы и выполнит проверку в фоновой задаче.
2. Проверьте состав файлов, готовность товаров и ошибки. Неизвестные значения
   остаются неизвестными: отсутствие строки остатка не означает нулевой остаток.
3. Примените проверенный пакет. Прогресс сохраняется в БД; после ошибки доступен
   повтор с последнего завершённого блока. Пока применение не завершено,
   расчёт по этому источнику запрещён.
4. В `/data/catalogs` откройте поставщика → его товары → карточку товара.
   Карточка показывает код 1С отдельно от артикула, единицы, условия заказа,
   источник и ограничения данных. Из поставщика можно перейти к его заказам.

Настройки импорта фиксируются вместе с пакетом. Срок поставки, смысл MOQ,
сопоставления складов и пересчёт закупочных единиц вводятся явно. Тестовые
значения не являются подтверждёнными условиями поставщика. Новая версия
условий того же источника требует увеличения `revision`.

## Идентичность и повторная загрузка

Внутренние ID — PostgreSQL UUIDv7 со встроенным временем. Код 1С хранится строкой,
включая ведущие нули и суффиксы. Таблица сопоставлений связывает источник,
код и характеристику с постоянным UUID товара. Артикул не является ключом.
Повтор идентичного пакета возвращает существующий пакет. Применение не создаёт
дубли товаров, поставщиков и уже принятых фактов.

В исходной динамике нет надёжного ID строки документа. Поэтому изменение
содержимого уже загруженной динамики в том же источнике запрещено: нельзя
безопасно отличить исправление от дополнительной продажи. Для полноценного
инкрементального обмена используйте нормализованный контракт 1С со стабильными
ID строк и версиями. Аналогичная защита действует для изменённых книг товаров
в пути и параметров, меняющих уже принятые факты: складов, периода истории,
даты среза, политики возвратов, единиц и ручных остатков. Изменения lead time,
семантики MOQ и версии разрешены. Это защищает от удвоения поставок и сохранения
старых продаж рядом с исправленными. Пакетный адаптер не устанавливает сетевое
соединение с 1С.

## Что сохраняется и что влияет на расчёт

| Данные | Обработка |
| --- | --- |
| Номенклатура всех книг | Объединение по коду 1С, а не пересечение перечней; связь с поставщиком. |
| Положительные расходные операции | Дневная история продаж с документом и единицей. |
| Отрицательные, неизвестные и ошибочные операции | Карантин с координатами; возвраты требуют явной политики. |
| Помесячные продажи, остатки, сезонность | Контрольная история; не складывается повторно с дневными продажами. |
| Текущие остатки Systeme | Количество и резерв отдельно; склад должен быть сопоставлен. |
| Товары в пути | Только с подтверждённым сопоставлением склада и единиц. |
| MOQ и кратность | Сохраняются раздельно; неоднозначные условия блокируют заказ. |

Для всех принятых фактов сохраняются исходные координаты и ячейки; большие
массивы разбиты на блоки и не попадают в обычный ответ API. Формулы из файлов
не исполняются; используются сохранённые значения с проверкой.

Без дополнительных параметров 12 книг дают 3 908 товаров
(3 184 IEK и 724 Systeme Electric) и 248 467 принятых продаж.
Все товары первоначально имеют статус `blocked`. Исторический месячный остаток
не разрешает заказ на текущую дату. Если условия явно дополнены, статус
`limited` сохраняет предупреждения об отсутствии клиентов и точных stockout.
Алгоритм не выдумывает клиентские ID или интервалы отсутствия товара.

## API и сопровождение

Актуальные тела запросов, ограничения и ответы — в `/docs` и `/openapi.json`.
Пакеты: `/api/v1/imports/packages`; операции проверки, применения и повторения
выполняются через существующую очередь Jobs. Каталог товаров принимает
`source_id`, `supplier_id`, поиск и пагинацию. Заказы принимают `supplier_id`.
Доступ контролируется существующими правами импорта, справочников и заказов.

Перед запуском обновлённой версии выполните Alembic upgrade и перезапустите
worker, чтобы зарегистрировались новые виды задач. Оригиналы находятся
в приватном файловом хранилище приложения, не в публичном frontend.

Календарный день расчёта и дата снимка запасов определяются в `Asia/Almaty`
для единой компании Электрокомплект. Например, `22.09.2026 00:00 +05:00`
хранится в PostgreSQL как `21.09.2026 19:00 UTC`, но относится к 22 сентября.
Запрос за предыдущий день исключает этот снимок; проверка давности также
использует местную дату. Исходные временные метки не подменяются UTC-полуночью.
