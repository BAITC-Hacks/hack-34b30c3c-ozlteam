## 1. Принципы

1. **Плоскость и глубина вместо линий.** Иерархию задают фон холста, белый блок и утопленная область внутри него. Рамок у блоков нет; единственная линия — волосяной разделитель `--hair` между строками одного списка.
2. **Один акцент.** Синий `--ac` — только для действия и активного состояния. Статусы — четыре цвета с мягкими подложками, у каждого «чернильный» вариант для текста. Цвет раздела или агента — для аватаров и точек, не для текста.
3. **ИИ предлагает, человек решает.** Любая рекомендация несёт уверенность в процентах и раскрываемое «Почему» с источниками. Действие проходит предпросмотр «что произойдёт» и явное подтверждение. Ничего не выполняется само и не всплывает без запроса.
4. **Состояния — часть компонента.** Покой, наведение, нажатие, фокус, недоступно, загрузка, пусто, ошибка и «модель считает» проектируются и сдаются вместе с компонентом.
5. **Отклик без задержки.** Hover применяется мгновенно (`transition-duration: 0s`), а возвращается в покой плавно за 200 мс; только на точном указателе. `:active` даёт `scale(.98)` за 100 мс; выезд панели — 320 мс с критическим демпфированием; отскок не используется.
6. **Настоящие слова.** Кнопка называет действие («Согласовать», «Записать»), статус — состояние («Ждёт согласования»). Без заглавных эйбрау, средних точек в мета-строках и нумерации там, где нет последовательности.

## 3. Типографика

Системный стек (`-apple-system, "SF Pro", "Segoe UI", system-ui`): нулевая загрузка, оптический размер и кириллица из коробки. Трекинг зависит от размера — крупный текст сжат, корпус на нуле:

| Роль | Размер / интерлиньяж / трекинг | Вес |
| --- | --- | --- |
| Заголовок страницы `h1` | 26 / 1.15 / −0.6 px | 600 |
| Крупная цифра плитки | 26 / 1.1 / −0.7 px, `tabular-nums` | 600 |
| Заголовок секции `h2` | 16 / 1.3 / −0.3 px | 600 |
| Заголовок карточки `h3` | 14 / 1.3 / −0.15 px | 600 |
| Корпус | 14 / 1.45 / 0 | 400 |
| Вторичный | 13 и 12,5 / 1.45 | 400, цвет `--mut` |
| Подпись | 12 | 400, `--mut` или `--faint` |
| Бейдж, счётчик | 11 / 1 | 500–600 |

Все числа — `font-variant-numeric: tabular-nums` (класс `.num`). Единицы измерения при крупной цифре не отделяются в мелкий текст; поясняющая строка под цифрой — 12 px `--mut`.

## 4. Каркас

```
┌──────────────┬────────────────────────────────────────────────────┐
│ сайдбар 236  │ шапка: h1 ─────── действия · поиск · кнопки панелей │
│ без фона,    │ сегменты (если есть)                               │
│ линия справа │ ряд чисел                                          │
│              │ cols(1.35fr | 1fr) — блоки --panel, радиус 16      │
└──────────────┴────────────────────────────────────────────────────┘
       фон рабочей области --shell, блоки белые --panel
```

- **Рабочая область** занимает окно браузера целиком, фон `--shell`. Рисовать внутри страницы ещё одну карточку со скруглением и тенью нельзя: получается блок в блоке, браузер уже даёт рамку. Лёгкость держится на другом — фон рабочей области чуть темнее белых блоков, поэтому они читаются как слои, а не как рисунок на фоне.
- **Левый сайдбар** — 236 px **внутри окна, без собственного фона и тени**, отделён волосяной линией. Две панели с тенями друг напротив друга утяжеляют экран; сайдбар — часть окна, а не отдельный блок. Бренд со штампом, группы «Работа» и «Справочники» обычным регистром, внизу карточка пользователя над линией. Активный пункт — `--ac-soft` с текстом `--ac-ink`, счётчики — пилюли.
- **Шапка страницы** (`app/PageHeader.tsx`) — `h1` и подзаголовок слева, **на одной линии** с действиями раздела, поиском `⌘K` и колокольчиком справа. Разносить заголовок и поиск на два этажа нельзя: это первое, что делает экран тяжёлым. Ниже — сегменты, если они есть.
- **Тёмный штамп** — иконка блока или ряда чисел лежит в квадрате `--stamp-size` цвета `--stamp` с белой иконкой. Это опора взгляда в разреженной сетке; серая подложка вместо него теряет ритм.
- **Контент** — сегменты → ряд чисел → блок ИИ → две колонки `minmax(0, 1.35fr)` / `minmax(0, 1fr)`. `minmax(0, …)` обязателен: с голым `1fr` таблица внутри распирает трек шире экрана. Секция = заголовок 16 px + счётчик + действие справа, под ним блок.
- **Правый рельс** — 58 px, вкладки 42×42 с подсказкой слева и счётчиком. Панель 404 px выезжает слева от рельса за 320 мс, без затемнения, контент под ней остаётся рабочим. В закрытом состоянии панель уведена за край **и** скрыта `visibility: hidden`, чтобы не перехватывать клики. Esc закрывает.
- **Отзывчивость.** ≥ 1101 px — полный каркас, контент получает `padding-right: 100px` под рельс. ≤ 1100 — две колонки контента складываются в одну, плитки 4 → 2. ≤ 900 — сайдбар и рельс скрываются, их заменяет нижняя панель навигации (см. ниже), панель ассистента занимает весь экран. Внутри блока используйте контейнерные запросы, не медиа: блок должен вести себя одинаково в галерее и на странице.
- **Нижняя навигация (≤ 900 px)** — четыре раздела и ячейка «Ещё», высота ячейки `--mobile-bar-h`, ниже добавляется `env(safe-area-inset-bottom)` под домашний индикатор iPhone. Прятать сайдбар без замены нельзя: без панели на телефоне нет ни перехода между разделами, ни выхода из аккаунта. Остальные разделы, карточка пользователя и выход живут в листе «Ещё», который выезжает снизу за `--t-panel`; закрывается той же ячейкой, тапом по затемнению и Esc. Панель лежит **поверх** листа, иначе кнопка закрытия оказывается под ним, а лист получает нижний отступ на высоту панели. В закрытом состоянии лист уведён за край, скрыт `visibility: hidden`, помечен `aria-hidden` и выведен из обхода по Tab. Если активен раздел из листа, подсвечивается «Ещё». Контент страницы получает нижний отступ на высоту панели. Полевые экраны прораба (Обходы · Отклонения) встают в те же четыре ячейки, когда направление продукта определится.
- **`viewport-fit=cover`** в `frontend/index.html` обязателен: без него `env(safe-area-inset-*)` возвращает нули и нижняя панель уезжает под системную полосу установленного PWA.

| **Modal** | общий backdrop, панель sm / md / lg, sticky-шапка и footer, опциональный body-only scroll; заготовки `ConfirmModal` и `FormModal`; на мобильном становится нижним sheet | стек LIFO, родитель остаётся смонтированным и `inert`, Escape/backdrop только для верхнего окна, `back` / `closeAll`, восстановление фокуса и scroll-lock |

**Тон подписей.** Цифра без смысла бесполезна. Там, где место позволяет, доля подписывается не диапазоном, а состоянием: «пора разобрать» вместо «старше 90 дней», «нормальный срок» вместо «31–60». Блок с цифрами заканчивается строкой-выводом: что именно происходит и что с этим делать. Плотность допустима, декоративный шум — нет.

## 6. Состояния и обратная связь

- Четыре вида обратной связи: статус (идёт), завершение (сделано), предупреждение (до проблемы), ошибка (после). Валидация inline, не по submit.
- Загрузка блока — скелетон в его форме, не спиннер по центру. Загрузка действия — pending на кнопке, интерфейс не блокируется.
- Пустое состояние — приглашение к действию с одной кнопкой, без иллюстраций.
- Ошибка — конкретная и с выходом: «Не удалось загрузить отправку. Повторить».
- Ожидание модели — компонент **Think**: пользователь видит, какие источники читаются. Ответ длиннее 3 с без шагов недопустим.

## 7. ИИ в интерфейсе

- **Уверенность** — всегда число и полоса; ниже 70 % — формулировки осторожнее, действие только вторичной кнопкой.
- **«Почему»** — список источников с конкретикой (лист, договор, дата, выборка). Раскрывается кнопкой, не при наведении.
- **Предпросмотр → подтверждение** — обязателен для всего, что меняет данные: закупка, сдвиг графика, назначение. В предпросмотре — эффекты по разделам и оговорка о том, чего действие не делает.
- **Откат** — если обратим, сказать об этом в Done.
- **Агенты** — у каждого заявленный доступ в шапке диалога («Видит: договоры, акты…»). Агент отвечает только в своей сфере и говорит, что смотрел. Агенты могут запрашивать друг друга; это видно в диалоге («Попросил Строителя»).
- **Строитель** контекстный: знает открытый раздел и меняет подсказки-чипы под него.
- **Маскот «Каска»** — только на вкладке Чаты и в шапке списка агентов. Моргает, реагирует на наведение, о новом сообщает счётчиком. Не появляется сам, не говорит первым, не двигается без действия пользователя.

## 8. Экраны

> Описания ниже сделаны под строительную гипотезу и предметно устарели. Оставлены как набор приёмов: какие блоки на экране, в каком порядке и что в них главное. Логистические экраны проектируются после публикации кейса.


**Сводка по объекту** — шапка объекта, сегмент периода, 4 плитки (освоение, отклонение по смете, прогноз срока, открытые отклонения), блок ИИ с главным риском дня, слева «Требует решения сегодня» — лента по всему конвейеру с глубокими ссылками, справа «Отклонения» (3 строки) и «Ход работ» (полосы факт/план).

**Отклонения** — фильтры-чипы, 4 плитки (в том числе «ложных срабатываний» — честность модели), список с миниатюрами кадров, уверенностью и статусом. Открытие строки → карточка отклонения (мобильный экран «Отклонение»: кадр с наложенной разметкой, что нашла модель, основание, уверенность, последствие, предложение и две кнопки «Подтвердить» / «Это не ошибка»).

**Смета** — плитки (всего, выше рынка, нет аналогов, проверено моделью), блок ИИ, таблица «позиция · объём · в смете · рынок · разница · действие». Позиции без выборки помечены «нет выборки», не подогнаны.

**Материалы** — плитки (дефицит, законтрактовано, излишек, ближайшая поставка), таблица потребности с колонкой «нужен к» и кнопкой «Закупить» из строки.

**Закупки** — сегмент статусов, три карточки-закупки (заголовок, сумма 22/600, срок, статус, ответственный, строка модели с процентом), блок ИИ с обоснованием выбора не самого дешёвого.

**График** — блок ИИ с прогнозом сдачи и предложением, Гант: план серым, факт цветом, критический путь `--er`, вертикаль «сегодня», легенда.

**Подрядчики** — блок ИИ (кого звать), сетка карточек: логотип-инициалы, имя, роль, три показателя, строка модели, статус.

**Чаты (правая панель)** — вид «список»: шапка с маскотом и числом агентов, список агентов; вид «диалог»: назад, аватар, имя, «Видит: …», лента сообщений с карточками, предпросмотрами и Done, поле ввода с вложением. **Уведомления / Документы / Задачи** — списки с цветной точкой источника и глубокими ссылками.

Кнопка «Назад» на карточках, формах и страницах деталей возвращает на маршрут входа с состоянием списка — правила в [`.agents/skills/contextual-back-navigation/SKILL.md`](../.agents/skills/contextual-back-navigation/SKILL.md).

**Каска ИИ** (`/assistant`) — экран диалога с моделью. Пусто: крупное приветствие по имени и четыре карточки-сценария с тёмными штампами; карточка сразу отправляет свой вопрос. Диалог: реплики человека справа `--ac`, ответы модели белым блоком слева, под ними состояние «Каска думает…». Поле ввода липнет к низу, Enter отправляет, Shift + Enter переносит строку; на тач-экране кнопка отправки растёт до `--touch`. История хранится у клиента и уходит на сервер с каждым вопросом — хранилища у чата пока нет. Ошибка провайдера показывается строкой-выводом и не стирает заданный вопрос.

**Маршруты** (`/routes`) — живая карта рейсов. Четыре плитки (в пути, стоят, нарушений, отставание), карта во всю ширину блока и под ней панель управления демонстрацией: режим «Авто / Ручной», ход, скорость, «Сначала», чипы «подбросить событие» и переключатель камеры «К рейсу / Весь регион». Ниже — карточка выбранного рейса с цепочкой точек и телеметрией, затем три колонки: «Рейсы», «Хронология» и «Разбор ассистента» с «Заказами без рейса». Порядок колонок повторяет ход мысли логиста: какой рейс → что случилось → что делать.

Карта — **отдельный материал, а не блок интерфейса**: тёмное полотно, на котором светится трек. Правило «один акцент» на неё не распространяется, потому что зелёный там несёт смысл пройденного пути и не появляется за пределами карты. Пройденное — сплошная линия со свечением, впереди — пунктир. Машина в пути пульсирует, стоящая окрашена в `--map-warn`. Подписи и толщины линий пересчитываются при наезде камеры, иначе на приближении карта зарастает жирными штрихами.

Разбор события идёт по общему правилу ИИ: вывод одной строкой, уверенность в процентах, раскрываемое «Почему», действия — только предложения, каждое проходит через предпросмотр «что произойдёт» и подтверждение человека. Под разбором честная подпись, ответила ли живая модель или показан заготовленный разбор.

**Мобильные экраны прораба** — «Обходы» (список осмотров с числом кадров и найденных отклонений, кнопка «Снять обход» в нижней панели) и «Отклонение» (см. выше). Строятся в языке iOS: крупный заголовок, сгруппированный список с внутренним отступом, нижняя панель действий 48 px, без нарисованного статус-бара.

## 9. Доступность

- Текст интерфейса по умолчанию не выделяется (`user-select: none`). Выделение возвращается только полям ввода, `pre`/`code`, `contenteditable` и содержимому, явно помеченному `.is-selectable` для копирования.
- Контраст текста ≥ 4,5:1: `--mut` и `--faint` на белом проходят, `--deco` — только для декоративных элементов.
- Фокус — `:focus-visible` 2 px `--ac` (на синем — `--ink`) с отступом 2 px; порядок табуляции соответствует визуальному.
- Цели нажатия на мобильных ≥ 44 px; на десктопе контролы 36, строки списков ≥ 40.
- `prefers-reduced-motion` — все переходы 1 мс; `prefers-reduced-transparency` — полупрозрачные поверхности становятся плотными; `prefers-contrast: more` — рамки `--ink` у блоков.
- Иконки только с текстом или `aria-label`; счётчики читаются как часть пункта.

## 10. Организация стилей

Дополняет `frontend-modules`, не заменяет.

- `frontend/src/shared/styles/tokens.css` — копия `docs/design/tokens.css`; `base.css` — сброс и элементные умолчания. Подключаются один раз в `main.tsx`.
- Общие примитивы — `frontend/src/shared/ui/<Name>/<Name>.tsx` + `<Name>.module.css`. Предметные компоненты — внутри модуля с `*.module.css`. CSS Modules идут с Vite без зависимостей и снимают конфликт глобальных имён между модулями.
- Глобальные селекторы по тегам — только в `base.css`. Текущий `app/styles.css` со стилями `header`, `h1`, `input`, `footer` нарушает модульность и заменяется по плану ниже.
- Иконки — `lucide-react`, штрих 1.8, размеры 16/17/19. Маскот — `shared/ui/Mascot`.

## 11. Открытые вопросы

- **Иконка маскота.** В прототипе пять вариантов с живым переключателем в шапке списка чатов: лицо под козырьком, каска без лица, каска в пузыре, бот, искра в пузыре. Рекомендация — «каска в пузыре»: про функцию вкладки, а не про персонажа.
- **Тёмная тема.** Токены готовы, второй набор значений — час работы; решение о необходимости не принято.
- **Набор иконок.** Предложен `lucide-react`; нужна одна установка зависимости.
- **Плотный режим** таблиц (строки 36 px) — переключатель через токены, не решено, нужен ли.
- **Клавиатура**: `⌘K` и J/K/Enter в очереди решений нарисованы, поведение не спроектировано до конца.
