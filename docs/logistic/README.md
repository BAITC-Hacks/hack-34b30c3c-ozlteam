# Предметная область: логистика

Справочник по внешнеторговой перевозке и растаможке, собранный под трек 05 «Логистика».
Нужен, чтобы команда и агенты понимали предмет до того, как заводить сущности в коде.

Это **карта местности, а не инструкция**. Устройство процедур и состав документов описаны
по Таможенному кодексу ЕАЭС, конвенциям CMR и СМГС и общей практике. Конкретные цифры, пороги,
сроки и обозначения форм помечены в текстах как требующие проверки: они регулируются
национальным законодательством и менялись.

## Что из этого важно для кода

Три вещи, которые прямо влияют на модель данных и уже расходятся с текущим прототипом:

**Не всякая граница — таможня.** Казахстан в ЕАЭС: с Россией и Киргизией таможенного оформления
нет вообще, только транспортный контроль. С Китаем — внешний контур союза, полный цикл.
С Узбекистаном — полноценная таможня, союз тут ни при чём. Симулятор в `frontend/src/modules/fleet`
пока держит все три границы одинаково.

**Типов рейса минимум три, и у них разные состояния.** Импорт заканчивается выпуском,
транзит — закрытием транзита в таможне назначения по назначенному сроку, экспорт — подтверждением
вывоза перед налоговой. У транзитного рейса есть таймер, который может сгореть.

**Режим труда и отдыха — часть плана, а не помеха.** Водитель едет девять часов и встаёт на
одиннадцать; без этого срок доставки занижается в разы. Это уже учтено в `lib/route.ts`.

## Как пересобрать

Исходники страниц и сборщики — в [source/](source). Нужен установленный Google Chrome.

```sh
cd docs/logistic/source && python3 build_pdf.py
```

Скрипт собирает печатные версии из исходных `*.html`, а PDF печатаются из них headless-браузером
(команда — в шапке `build_pdf.py`). `restyle.py` раскатывает общее оформление серии по всем
страницам, `rail_build.py` собирает страницу про железную дорогу из общего стиля и своих данных.

Оформление у всех четырёх общее и построено на визуальном языке бланка таможенной декларации:
графы с волосяными линиями, моноширинные подписи, штемпельная краска, защитная сетка.
